# The squash commit message: the change's verification record (ADR-k3nkv3).
# merge-change step 5 writes it to `gr_message_file` from this template;
# `ratchet` step 5 writes it early for a ratchet change, and merge-change step 5
# updates it. Step 6b adds Base:, Gate-tree:, Tests: and Coverage:;
# check-review.sh checks it before the hand-over and finish-merge.sh after
# signing. Lines opening with `#` are guidance: the hand-over commits with
# -c core.commentChar='#' and --cleanup=strip, which removes them, and the
# checker drops them first.
# Replace every <placeholder>, or delete a line that does not apply: a review
# field, disposition or trailer still holding one counts as missing.

# Items:, Problems:, Red-green:, Gaps: and Qualification: are prose for
# people, which the step 4 reviewer checks. Items: lists each REQ, LLR,
# SDD, HAZ or RC item the change adds, rewords, replaces (`old → new`) or
# deletes (with the reason); it is the only record of a deleted item. PR
# items go under Problems:, which lists each PR item resolved, as
# `PR-<id> — <cause> → <fix>`. The message check reads only
# deletions: each REQ, LLR, SDD, HAZ or RC the diff deletes must appear under
# Items:, and each PR it deletes under Problems:. Each section runs to the
# first blank line after its list, or the next section header; a blank line
# between the header and its list is allowed. Red-green lines are copied
# verbatim from the dispatch reports. Qualification: is a ratchet change's
# only.

# One line per finding, `<N>. [<disposition>] <tag>[ <severity>] — <text>`,
# continued on lines opening with whitespace and not then `<N>. `; the
# section ends at the next blank line. Number the findings here; after the
# disposition, copy the reviewer's finding verbatim minus its label
# (`**finding-N**:`).
# Tags: code, requirement, guideline (each with a severity: high, medium
# or low) and record (none). Dispositions: [fixed: <cite>, …],
# [open: <cite>], usually a PR item ID, [no change: <reason>], each with
# text after its colon; any other form is malformed. A record finding may
# cite `message`. No Findings: section means the review raised nothing,
# and no other body line may open with `<N>. `.

# Trailers, the last paragraph, read with git interpret-trailers. Exactly one
# Base:, not empty. Exactly one Gate-tree:, the squash's own tree. Exactly
# one Tests: per verify_commands entry and one Coverage: per
# coverage_command, over the units of the change's impact set under a units
# manifest (check-units.sh --impact); none where none is configured, but at
# least one Tests:, with or without a configuration, each ending
# <passed>/<total>, passed equal to total. Mutation: only where a mutant is

# the trailer paragraph: git reads trailers only from the last paragraph, so a
