# Problem reports — macOS awk portability

Guardrails keeps no requirements, risk or architecture ledger of its own yet:
`docs/plans/2026-08-22-ratchet-gap-analysis.md` measures why installing the
machinery on this repo is blocked behind a scan-exclusion mechanism it does
not have. This is the first ledger directory to exist here, created because a
problem needed recording and a problem report has nowhere else to live. It
does **not** mean the rest of the machinery is installed; `.guardrails/` is
still absent and no gate runs on this tree.

`affects:` therefore names the script and function implicated rather than an
item ID, because there is no item to name. When the ledgers arrive, these
lines get the IDs.

**PR-v3j4s2**: `check-review.sh` exits 2 before it reads any record on macOS,
so the step-6c review gate cannot run at all on that platform.
affects: scripts/check-review.sh `scan_record` — no REQ/SDD/LLR ledger exists
here yet, see the note above.
opened: 2026-08-26
status: resolved
`scan_record` interpolated the newline-separated GR_RECORD_FIELDS straight into
`awk -v kws=`; awk now reads GR_RECORD_KWS, the same list flattened to spaces,
leaving GR_RECORD_FIELDS and the newline-dependent `for _kw in
$GR_RECORD_FIELDS` loop alone. Reproduced on any platform by `tests/portability.bats:check-review: runs
under an awk that refuses a newline in -v`, and the class is swept by `every
check script runs clean under an awk that refuses a newline in -v`.

**PR-yd2sft**: `days_ago` cannot produce a future date on BSD `date`, so the
two clock-skew tests never reach their assertions on macOS.
affects: tests/helpers.bash `days_ago`; tests/check-trace.bats — the
`MALFORMED-DATE`/future-date gate is the behaviour left unexercised.
opened: 2026-08-26
status: resolved
`days_ago` spelled the sign twice for BSD `date`, handing it `-v--1d` for a
negative count; the sign is now folded into the adjustment. Reproduced by
`tests/portability.bats:days_ago produces a date in the future as well as one
in the past`.

**PR-44z762**: `tests/lib.bats` calls `sed -i` with no backup suffix, which
BSD `sed` reads as the suffix, so the shipped config template is never checked
against the schema on macOS.
affects: tests/lib.bats — and `AGENTS.md`, which already states the `sed -i.bak`
rule that nothing enforces.
opened: 2026-08-26
status: resolved
The one call out of line with the repo's own rule now uses `sed -i.bak` and
removes the backup. The rule is enforced from here by
`tests/portability.bats:no in-place sed in the repository omits its backup
suffix`, which greps every executable path — `scripts`, `tests`, `templates`,
`skills`, `install.sh` — rather than the one site. It does NOT reach `docs/`;
the mutation scripts there carry the same defect and are PR-aap8nx.

**PR-mu8ybm**: Nine `sed -i` calls with no backup suffix arrived on the base
branch in 590867a, and six of `tests/lib.bats`'s new config-schema tests fail
on macOS because of them.
affects: tests/lib.bats — the `gr_check_config` rules that commit added are the
behaviour left unexercised on BSD userland.
opened: 2026-08-27
status: resolved
Found by the lint added for PR-44z762 on its first contact with new code,
during the step-1 base merge. Six sites gained the `.bak` suffix; three could
not be fixed that way at all — `0,/re/{/re/d}` and `/re/,+1d` are GNU-only
addresses BSD sed rejects outright — and became `del_first_line` in
tests/helpers.bash, a portable whole-line delete. Reproduced by the six
`tests/lib.bats` config-schema tests that were red on macOS and by
`tests/portability.bats:no in-place sed in the repository omits its backup
suffix`.

**PR-aap8nx**: Sixteen `sed -i` calls with no backup suffix sit in the mutation
scripts under `docs/verification/*.mutations/`, so re-running this project's own
mutation evidence dies on BSD sed.
affects: docs/verification/2026-08-20-scan-pathspec.mutations/ and
docs/verification/2026-08-22-id-tokens.mutations/ — the mutation-testing
evidence behind those two changes' verification records.
opened: 2026-08-27
status: open
Left open deliberately. Found by the independent review of the PR-44z762 lint
(finding 6). These are prior changes' verification artefacts, not this change's
code, and widening the lint to cover them would redden this merge on files no
part of this change touched. Rewriting sixteen evidence scripts is its own
change with its own review.

**PR-w8k3np**: `make_bsd_date` refuses valid `-v` adjustments on every platform
except the one it exists to simulate, so both tests using it fail on a GNU box.
affects: tests/helpers.bash `make_bsd_date` — no REQ/SDD/LLR ledger exists here
yet, see the note above.
opened: 2026-08-28
status: resolved
The stub validated `-v` and then `exec`ed the REAL date with it unchanged.
Accepting an option is not the same as carrying it out: on a GNU or uutils box
the real date has no `-v` at all, so the stub reproduced BSD's rejections and
none of its successes, and `date -v-3d` — the valid case — was refused. It now
translates `-v±Nd` into `-d "N days [ago]"` where the real date understands
`-d`, and passes it through where it does not. Both failures were inherited
rather than introduced: measured by running the suite from `git archive main`
in a clean directory, with none of the change under test present.
