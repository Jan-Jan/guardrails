# Problems found by base-premise-lapsed

**PR-z83ka9**: The condition ADR-y8jmes's Scope states it rests on — "local
`main` contains every ID that was merged" — does not hold in this repository,
so `merge-change` step 4's DUPLICATE-ID scan reads a set of IDs that is
missing every ID merged on another machine.
affects: ADR-y8jmes, whose Scope paragraph makes that condition the reason the
skipped fetch is safe here, and whose "Why the cost is accepted here" rests on
it; AGENTS.md non-negotiable 4, which points at the ADR for the argument.
opened: 2026-10-13
status: resolved
Resolved 2026-10-13 by this change: ADR-y8jmes's Scope now states that the
condition is about the machine, not the maintainer, and that reconciling local
`main` with the remote is the maintainer's call, carried out by an agent only
where the maintainer directs that explicitly; AGENTS.md non-negotiable 4 states
the same permission where an agent reads the rule. No script changed for this item: the lapse was in the
decision's premise, and no gate was misreporting. The same change also carries
the content merged on the other machine into local `main`, so the seven IDs
named below are present to step 4's scan. Because a change integrates as a
signed squash, their commits do not become ancestors of `main`: what the remote
relationship should be next is the maintainer's to decide, and this item does
not decide it.
Measured 2026-10-13. Local `main` is at be9cfa6 and the remote-tracking
`origin/main` at d015a48, their merge base 1967dc8. Seven PR IDs are defined
under `docs/` on `origin/main` and on no local ref — PR-8zcc72, PR-ad4vmm,
PR-cjvv8g, PR-gw6wts, PR-nhf8cy, PR-qm5gfy and PR-x63ejd — while PR-8um9a9
and PR-z7w5bf are defined on local `main` and not on `origin/main`. A change
branched from local `main` therefore merges a base that cannot contain those
seven, which is precisely the set the ADR's reasoning assumes is empty. No
collision exists today: the two sets are disjoint, so the residual risk the
ADR names is latent, not realised. The lapse is in the premise, not in any
script — `new-id.sh` discards a candidate present anywhere in the tree, and
the tree it can see is now a proper subset of what was merged.
