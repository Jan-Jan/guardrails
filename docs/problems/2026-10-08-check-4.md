# Problem report — supersession's dual `verifies:` line against verify-before-merge check 4

Reported by a class C adopter at 646fa1f. `affects:` names files, because
guardrails keeps no REQ/SDD/LLR ledger of its own.

**PR-kzst5n**: The supersession form tells the author to add the new ID to the test that verified the superseded item, an already-green test, while `verify-before-merge` check 4 fails a `verifies:` test with no red-to-green attestation and forbids re-annotating a test that was green from the start, so a meaning-changing supersession can satisfy one rule only by breaking the other or by writing a duplicate test to carry the ID.
affects: skills/grill-requirements/references/supersession.md, skills/merge-change/references/review-checklist.md, skills/verify-before-merge/SKILL.md (check 4) and references/rationale.md, scripts/check-trace.sh (MISSING-TEST does not read `superseded-by:`); also the missing recorded form for retiring an item whose behavior is gone.
opened: 2026-10-08
status: resolved
Root cause: the dual-ID rule was written when no script read `supersedes:` or
`superseded-by:`, so the only way to keep MISSING-TEST clean without a gate
change was to make the old green test carry the new ID, which check 4 forbids.
Fixed by docs/plans/2026-10-08-out-of-force-items.md: a superseded (reciprocal
pair) or retired (`retired: YYYY-MM-DD — <reason>`) REQ or LLR is out of force
and owes no test, discharges no `satisfies:` or `implements:`, and a
`verifies:` line naming only out-of-force items fails as
OUT-OF-FORCE-VERIFIES; check 4 reads per ID and names a re-pointed test of a
predecessor as `inherited:`. Reproduced by `check-trace: a superseded REQ with
a reciprocal pair owes no test` and `check-trace: a retired REQ owes no test`
(tests/check-trace.bats), each watched failing first.
