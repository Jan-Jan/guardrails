## Cause

bats strips the quotes around a test name and evaluates the remainder as a
double-quoted shell string, for single-quoted names as well. Measured with the
vendored Bats 1.11.0 on 2026-10-05:

| source | TAP output |
|---|---|
| `@test "a \\001 b"` | `a \001 b` |
| `@test "quote \" dollar \$HOME tick \` end"` | `` quote " dollar $HOME tick ` end `` |
| `@test "lone \q backslash"` | `lone \q backslash` |
| `@test 'single \\ quoted'` | `single \ quoted` |

So a backslash followed by `\`, `"`, `$` or `` ` `` is removed, and every other
backslash is kept. `tests/evidence.sh` reads names from the source at three
places and applies none of this. Line numbers in this plan are those of `35570e8`:

- line 77, `names_of`, the current names;
- line 82, the base names;
- line 127, the names submitted to the base run.

Line 127 against the TAP names at line 125 is the exit 2 that `PR-9aaart`
records, raised by `tests/task-worktree.bats:173`. Line 144 has the same fault
without an error: a new test whose name contains an escape never matches the
pass list, so it is counted as going red although it passed.

An unescaped `$name` in a test name would be expanded by bats. No test in this
repository has one, and the fix does not handle it. The script header states
this.

## Evidence limit

`tests/evidence.sh` is in `tests/`, and its base run copies the current
`tests/` (line 45). A test of `evidence.sh` therefore runs the current
`evidence.sh` in the base run as well, and it cannot go red against `main`.
`evidence.sh main` lists the new tests under "cannot go red". The red→green
proof for this change is the T1 red run, which the record copies.
