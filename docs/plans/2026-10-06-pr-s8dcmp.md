## Decisions

- **D1. Upgrade is its own mode** (`ADR-3h4dky`). Step 1 says that it has its
  own procedure and no gap analysis, and points to `references/rationale.md`
  for the reason.
- **D2. Done when has an upgrade entry.** The scripts and the files that
  document their grammar come from one guardrails version, and each new finding
  is fixed or listed in a plan in `docs/plans/`. Upgrade step 4 states the same
  action, so the procedure produces what Done when checks.
- **D3. The retrofit inventory drops "the `.guardrails/` version if
  re-ratcheting".** A project that has one is an upgrade (D1), so the clause
  routed a re-ratchet into the wrong mode.
- **D4. Word budget.** `SKILL.md` is at 1988 of 2000 words. To make room:
  - Upgrade step 5 (the macOS `check-review.sh` pass) moves into the order of
    work in `references/upgrade-notes.md`. The section it summarises, "On
    macOS, older versions of `check-review.sh` never executed", is already
    there, so nothing is lost.
  - The retrofit sentence on a monolithic `srs.md` is shortened, and keeps
    both of its facts.
  The result is 1999 words, measured on a scratch copy.

Out of scope: the scripts, the `upgrade` Red flag (already correct), README.
Problem reports consulted, none contradicted: PR-uavq3f (the upgrade
re-copies the READMEs, and its test still holds), PR-n274s7 (its test anchors
on upgrade step 4's text, which is kept).
