# ADR IDs: random tokens, as for problem reports

**Goal:** An ADR is an item with a random ID minted by `new-id.sh ADR`, in a
file named by that ID, in the skills, the shipped config and this repository.
**Implements:** D1 to D4 below (D3 and D4 ruled after review round 1). No REQ items exist in this repository.
**Safety class:** the toolkit is unclassified; the class B rules in `AGENTS.md`
apply. T1 may find a script change is needed; it stops and reports first.
**Verification:** `sh tests/run-tests.sh` — every test passes. `check-ids.sh`
and `check-trace.sh` under `scratchpad/gate/gr-config.yaml` report nothing that
a clone of `main` does not also report. That config keeps `id_prefixes: PR`:
with `ADR` declared, the ADR literals that tests in `tests/check-trace.bats`
use as fixtures are reported as `DANGLING-REF` (T1). IDs are minted under a
copy of it that adds `ADR`.

Run single bats files with `tests/.bats-core/bin/bats <file>`, never with
`tests/run-tests.sh <file>`.

## Decisions (the maintainer, 2026-10-04)

**D1 — an ADR has a random ID.** Sequential numbers clash across branches, and
dated names are wrong for a decision that is true regardless of date. Mint the
ID with `new-id.sh ADR`. The file is `docs/adr/ADR-<token>-<slug>.md`, one
decision per file, and it opens with the item line
`**ADR-<token>**: <the decision in one sentence>`. Cite an ADR by its ID.

**D2 — `ADR` is a declared prefix.** The shipped `templates/config.yaml` lists
`ADR` in `id_prefixes`, so `new-id.sh` mints it and `check-ids.sh` reports a
duplicate, malformed or draft ADR ID as it does for `PR`.

**D3 — a unit's ADR lives in the unit (2026-10-05, after review round 1).**
In a multi-unit repository, a decision that a unit cites by ID is in that
unit's `docs/adr/`, inside the scope `check-trace.sh` reads for the unit. A
decision that spans units is in the root `docs/adr/` and is cited by path. No
script change.

**D4 — `segregated_from:` accepts an ADR ID (2026-10-05, after review round
1).** `check-units.sh` accepts `(ADR-<token>)` where a file
`docs/adr/ADR-<token>-*.md` exists, at the repository root or in the consumer
unit, as well as `(RC-…)` and `(adr: <path>)`. After review round 2: the token
is a random token (finding 11), and the file's first line is
`**ADR-<token>**:`, the form D1 gives (finding 10).

## Upgrade concern

A project with sequential ADR headers (`**ADR-0007**:`) or dated files that
adds `ADR` to `id_prefixes` may see new `check-ids.sh` or `check-trace.sh`
findings. T1 measures which; T2 states the upgrade step in
`skills/ratchet/references/upgrade-notes.md`.

```bash
@test "ADRs: every file in docs/adr is named by the ID its item line defines" {
    # verifies: D1 (docs/plans/2026-10-04-adr-ids.md)
    cd "$BATS_TEST_DIRNAME/.." || return 1
    failures=""
    for adr_file in docs/adr/*.md; do
        adr_id=$(basename "$adr_file" | sed -E 's/^(ADR-[a-z0-9]{6})-.*/\1/')
        if ! head -5 "$adr_file" | grep -q "^\*\*$adr_id\*\*: "; then
            failures="$failures $adr_file"
        fi
    done
    [ -z "$failures" ] || { echo "ADR files not named by their item ID:$failures"; return 1; }
}
```
